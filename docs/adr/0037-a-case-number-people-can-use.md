# ADR-0037: A grievance carries a case number people can use

- **Status**: Superseded by [ADR-0038](0038-grm-case-numbers-run-in-sequence.md)
- **Date**: 25 September 2026
- **Owner**: NSR MIS Architecture Team
- **Decision-makers**: Registry owner (jmwebaze), GRM Lead (MGLSD), Engineering Lead
- **References**: ADR-0002 (identifier strategy); CLAUDE.md (*"Identifiers are ULIDs. Never sequential integers for externally-visible IDs."*); `apps/grievance/reference.py`

## Context

ADR-0002 made `Grievance.id` a ULID and called it "the citizen-facing
reference code". In practice it is `01M3AT4JSSXFYG02CXC8S6K20X`.

That is the right primary key — unique without coordination, sortable
by creation time, no sequence to leak how many cases the registry
holds — and the wrong thing to say out loud. A Parish Chief reads a
case number back to a citizen over the phone, writes it in a ledger,
and quotes it on a follow-up visit two weeks later. Twenty-six
characters with no grouping cannot survive that. Every transcription is
a chance to drop a character, and nothing in the string tells you when
one has been dropped.

The registry owner put it plainly: *"These GRM numbers are very hard to
remember and use."*

## Decision

A grievance carries a **reference** alongside its id:
**`GRM-7K4P-2QX9`**.

- **Eight significant characters, Crockford base32**, grouped in fours.
  The same alphabet the ULID already uses, so nothing new has to be
  explained to anyone.
- **Crockford because of what it leaves out.** No I, L, O or U — so
  there is no I/1 or O/0 to confuse, and no U to let a random string
  spell something unfortunate on a government slip. Its decoding rules
  also map the mistakes people actually make: O read as zero, I or l
  written for one. `normalise()` applies them, which is most of the
  value here over a plain random string.
- **Random, not sequential.** A running number would read slightly
  better and would tell anyone holding two references how many
  grievances the registry took between them, as well as letting them
  walk the range. CLAUDE.md forbids sequential externally-visible
  identifiers for that reason. 32^8 ≈ 1.1×10^12, the column is unique,
  and generation retries — so a collision is a retry, not an incident.
- **`secrets`, not `random`.** This is an identifier people will quote;
  a predictable one invites guessing even where the scope check is what
  actually protects the record.

**The ULID does not move.** It stays the primary key, stays in every
URL, stays in `linked_change_request_id`-style references and stays in
the audit chain. ADR-0002 is unchanged except that the phrase
"citizen-facing reference code" no longer describes `Grievance.id`.

**Both are shown.** The console leads with the reference and keeps the
ULID small underneath it, because the ULID is what a URL and an audit
row carry and hiding it would make those unmatchable.

**Lookup is server-side.** `?q=` normalises before matching, using the
same module the reference was generated with. A second implementation
of "O means 0" in JavaScript is how the two come to disagree.

**Searching is not a way round scope.** `?q=` filters the queryset
`visible_grievances` already returned, so a number somebody was told
still only opens a case they may see.

## Consequences

**GRM only, for now.** ChangeRequest has the same problem — ADR-0002
names its ULID as a citizen-facing reference too — and DataRequest and
Referral are quoted to people as well. `apps/grievance/reference.py` is
written so the prefix and the grouping are parameters, but nothing else
adopts it yet. That is a deliberate stop, not an oversight: each of
those is a separate decision about what its users actually quote.

**Existing grievances were backfilled**, so no case is without a
number. The backfill generates in Python rather than PL/pgSQL, because
the alphabet, the grouping and the collision retry live in one module
and a second implementation in SQL is how two grievances end up with
references generated by different rules.

**The reference never changes.** A number quoted to a citizen has to
keep meaning that case, so it is assigned once at creation and no
transition touches it.

**Eight characters is a judgement.** It is short enough to read aloud
and long enough that guessing is not a route in. If GRM volume ever
approaches a million cases, the birthday bound is worth revisiting —
the unique constraint will surface it as retries long before it
surfaces as a collision.
